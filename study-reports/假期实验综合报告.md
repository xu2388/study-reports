#### 1.3.4 实验9：KV 缓存加速

**核心思想**：自回归生成时，每层独立缓存 (k, v)，生成新词元时只对新增位置做投影，避免 O(T²) 全序列重算，实现 O(T) 线性加速。

![KV缓存加速](plots/kv_cache_speedup.png)
*图1-3 KV缓存加速效果。蓝线为朴素生成(~O(T²))，橙线为KV缓存(~O(T))。横轴为生成的词元数T，纵轴为耗时(秒)。在1000词元时，朴素版需19.7秒，缓存版仅需6.9秒，加速比达2.8倍。*

**加速比实测**：
| 生成长度 | 朴素耗时 | 缓存耗时 | 加速比 |
|---|---|---|---|
| 100 词元 | ~2.1s | ~1.5s | **1.4x** |
| 300 词元 | ~5.3s | ~2.8s | **1.9x** |
| 1000 词元 | 19.7s | 6.9s | **2.8x** |

4. 重构奖励函数以匹配六子棋战术价值

### 2.2 模型架构

#### 2.2.1 整体结构

```
Input (B, 2, 10, 10)  ← 2 通道（黑方/白方位置）
  ↓
Stem: Conv3×3(2→C) → BN → ReLU
  ↓
Body: N × SEResBlock(C)  ← 带 SE 注意力的残差块
  ↓
┌─────────────┬─────────────┐
│ Policy Head  │ Value Head  │
│ Conv1×1→32   │ Conv1×1→32  │
│ Conv1×1→1    │ AvgPool→FC  │
│ → (B, 100)   │ → (B, 1)    │
└─────────────┴─────────────┘
  ↓            ↓
策略预测      局面价值
(落子偏好)    (胜负概率)
```

#### 2.2.2 SE 注意力机制

```python
class SEBlock(nn.Module):
    def __init__(self, channels, reduction=8):
        # Squeeze: 全局平均池化 → (B, channels)
        self.squeeze = nn.AdaptiveAvgPool2d(1)
        # Excitation: 两层 FC + Sigmoid
        self.excitation = nn.Sequential(
            nn.Linear(channels, channels//reduction),  # 压缩
            nn.ReLU(),
            nn.Linear(channels//reduction, channels),  # 恢复
            nn.Sigmoid()  # 输出 0~1 权重
        )
    
    def forward(self, x):
        y = self.squeeze(x).view(b, c)
        y = self.excitation(y).view(b, c, 1, 1)
        return x * y  # 通道级加权
```

#### 2.2.3 SEResBlock（核心构建块）

```python
class SEResBlock(nn.Module):
    def __init__(self, channels):
        self.conv1 = nn.Conv2d(channels, channels, 3, padding=1)
        self.bn1 = nn.BatchNorm2d(channels)
        self.conv2 = nn.Conv2d(channels, channels, 3, padding=1)
        self.bn2 = nn.BatchNorm2d(channels)
        self.se = SEBlock(channels)
        self.relu = nn.ReLU()
    
    def forward(self, x):
        residual = x
        out = self.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        out = self.se(out)  # SE 注意力加权
        out = self.relu(out + residual)  # 残差连接
        return out
```

### 2.3 训练流程

#### 2.3.1 AlphaZero 训练循环

```
┌─────────────────────────────────────────────────────┐
│                  主训练循环                          │
│                                                      │
│  1. 自博弈 (Self-Play)                               │
│     ├── MCTS 搜索 (300 次模拟/步)                    │
│     ├── 生成训练数据 (state, π_mcts, z)              │
│     └── 对称增强 (8×)                                │
│                                                      │
│  2. 数据存入 Replay Buffer                           │
│     └── 容量 200,000，环形缓冲                       │
│                                                      │
│  3. 神经网络训练                                     │
│     ├── 策略损失: L_policy = -Σ π_mcts · log(p_net)  │
│     ├── 价值损失: L_value = MSE(v_pred, z)          │
│     └── 总损失: L = L_policy + L_value + λ·‖θ‖²     │
│                                                      │
│  4. 对手池更新                                        │
│     └── 定期保存历史模型作为对手                     │
│                                                      │
│  5. 定期评估 + 保存权重                               │
│     └── Elo 评级 + checkpoint                        │
└─────────────────────────────────────────────────────┘
```

#### 2.3.3 自博弈数据生成

每局自博弈流程：
1. 先手第一手随机落子
2. 每步：温度退火（前30步 τ=1.0，之后 τ=0.1）
3. 规则短路：检测必胜/必防棋形
4. MCTS 搜索：收集 300 次模拟结果
5. 采样落子：按 MCTS 策略采样
6. 终局标注：所有步骤标记胜负 z ∈ {-1, 0, +1}

```
    └── standard/    # Standard 模型历史备份（20+ 份）
```

### 2.8 训练关键问题与解决方案

| 问题 | 现象 | 原因 | 解决方案 |
|---|---|---|---|
| REINFORCE 损失爆炸 | Loss 从 -1626 爆到 -1390 万 | 负奖励主导梯度反转 | baseline 标准化 + tanh 缩放 |
| 1455 虚拟内存错误 | 多进程方案崩溃 | 14 个 Python 进程 + CUDA 触发 Windows 提交限制 | 改用单进程 GPU 模式 |
| 训练速度过慢 | 每步 0.04s 太慢 | MCTS 模拟次数过多 | FP16 + batch 256 + 调 num_simulations |
| 模型不会防守 | 对局始终 ~19 步 | 自博弈同质化 | 注入异质对手（Small 模型） |
| Elo 指标失真 | 永远 1500 左右 | 对手太弱（随机棋手） | 关注 Loss 和 game_len 指标 |

### 2.9 实验小结

**已完成**：
1. ✅ 五子棋→六子棋改造（胜利条件、棋形检测、奖励函数）
2. ✅ REINFORCE 方案训练（发现损失爆炸并修复）
3. ✅ AlphaZero Small 模型训练（20,000 局，6.4 小时）
4. ✅ AlphaZero Standard 模型训练（30,912 局，续训中）
5. ✅ GUI 人机对战系统
6. ✅ 断点续训、自动保存、对手池进化机制

**发现的问题**：
1. Small 模型棋力不足（容量瓶颈）
2. Standard 模型进攻强但防守弱（自博弈同质化）
3. Elo 评估体系需改进（当前仅对战随机棋手）

**下一步计划**：
1. 完成进化训练（注入 Small 对手），观察防守能力变化
2. 如进化训练无效，考虑训练专门的防守型模型
3. 改进 Elo 评估体系，引入历史模型对战
4. 探索更大棋盘（15×15）训练

## 第三部分：综合对比与展望

### 3.1 两个实验的技术对比

| 维度 | NanoGPT | 六子棋 AI |
|---|---|---|
| 算法 | Transformer (NLP) | AlphaZero (RL) |
| 训练方式 | 监督学习（预训练） | 强化学习（自博弈） |
| 数据来源 | 固定文本（Shakespeare） | 实时生成（自博弈） |
| 模型参数量 | 0.66M | 3.0M |
| 训练时间 | ~30 分钟 | ~10 小时 |
| 硬件要求 | CPU 即可 | 必须 GPU |
| 评估方式 | 困惑度（Loss） | Elo + 人机对战 |
| 核心技术 | 注意力机制、KV 缓存、LoRA | MCTS、残差网络、SE 注意力 |

### 3.2 核心收获

1. **模型架构设计**：掌握了从 Decoder-only Transformer 到 ResNet+SE 注意力的不同架构设计思想
2. **训练技巧**：学习了余弦退火、LoRA 参数高效微调、AMP 混合精度等实用技巧
3. **强化学习实战**：深入理解了 AlphaZero 的自博弈训练循环、MCTS 搜索、对手池进化机制
4. **工程问题解决**：解决了损失爆炸、虚拟内存限制、GIL 多线程瓶颈等实际问题

### 3.3 改进方向

| 方向 | 具体措施 |
|---|---|
| 六子棋模型 | 引入异质对手、训练防守型模型、扩大棋盘 |
| NanoGPT 扩展 | 更大数据集、更长上下文、RAG 优化 |
| 评估体系 | 引入 Elo 对战历史模型、增加胜率可视化 |
| 工程优化 | 多 GPU 分布式训练、模型量化部署 |
