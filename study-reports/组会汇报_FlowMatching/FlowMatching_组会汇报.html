概率图模型 · 模型表示

用图结构分解高维联合分布

图模型回答三大基本问题：表示、推断、学习。高维联合分布参数爆炸（2 值 100 维变量需约 10³⁰ 个参数），借助图结构把条件独立假设显式化，将联合分布拆成一族局部、可计算的因子。
有向图贝叶斯网络 · DAG
p(x) = ∏k p(xk | xπk)
  • 联合概率 = 各节点局部条件概率的连乘
  • 条件独立判定：链式 / 分叉观测中间节点即阻断路径；汇聚结构观测后反而引入依赖（解释消除）→ d-分离
  • 局部马尔可夫性质：给定父节点，与所有非后代条件独立
  • 典型模型：朴素贝叶斯、隐马尔可夫模型（HMM）、Sigmoid 信念网络
无向图马尔可夫随机场 · MRF
p(x) = (1/Z)·∏c φc(xc)
  • 按最大团上的势函数分解（Hammersley–Clifford 定理）
  • 势函数取指数形式即玻尔兹曼分布：φc(xc) = exp(−Ec(xc))
  • 配分函数 Z 需对全空间求和（指数级）——推断与学习的关键难点
  • 典型模型：对数线性模型（最大熵）、条件随机场（CRF）
关键区别：有向图按条件依赖逐点分解、可局部独立处理；无向图按最大团 / 势函数分解，配分函数 Z 耦合所有变量。有向 → 无向转换需道德化（为有共同孩子的父节点加边）。
概率图模型 · 推断

推断：从精确到近似

给定部分观测变量 e，求其他变量 q 的条件概率 p(q | e)，核心是求边际分布；结构越复杂、变量越连续，越需要转向近似推断。
精确推断树 / 无环结构
p(q | e) = Σz p(q, e, z) / Σq,z p(q, e, z)
  • 1变量消除法：乘法分配律 + 动态规划逐个消除变量；消除顺序决定中间因子规模
  • 2信念传播（和积 / 消息传递）：消息 μ 递归计算并缓存，链上复杂度由 O(KT) 降至 O(T·K²)
  • 3树结构：叶子 → 根 → 叶子一轮双向传播，即得所有变量的边际分布
  • 4有环：联合树算法转换为无环图后精确推断
近似推断有环 / 连续 / 高维
  • 环路信念传播（LBP）：在环上仍跑消息传递，不保证收敛与精确
  • 变分推断：用简单分布 q 逼近后验 p(z|x)，最大化 ELBO；平均场假设 + 坐标上升，摊销推断 → VAE
  • 采样法：拒绝采样、重要性采样、MCMC（Metropolis–Hastings、吉布斯采样）
要点：精确推断依赖树 / 无环结构与条件独立；一旦有环、变量连续或含高维隐变量，就转向变分或采样的近似路径。

六子棋（Connect6）AlphaZero：训练逻辑优化与成果

将五子棋 AlphaZero 项目改造为六子棋，并在 8G 显存的笔记本 GPU 上完成训练效率优化、断点续训与棋力提升。

方法框架

  • MCTS 搜索 + 双头网络（策略 π / 价值 v）
  • 自博弈（self-play）+ 对手池 + replay buffer
  • 8× 对称增强；胜利条件参数化（--win_condition 6），无需修改胜负检测代码

模型架构：SE-ResNet

  • 残差块 + SE（Squeeze-Excitation）通道注意力
  • Small：channels=64 × 8 块，约 300K 参数
  • Standard：channels=128 × 10 块，约 1.5M 参数

训练效率优化（8G 显存）

  • MCTS 批量推理：每个搜索迭代收集 256 个叶子节点一次性 GPU 前向，减少 GPU 调用
  • FP16 混合精度：autocast + GradScaler，显存利用率显著提升
  • 实测训练速度接近翻倍（多线程方案受 GIL 限制后回滚为串行 GPU 模式）

工程化能力

  • 断点续训：checkpoint 保存模型 + 优化器 + 调度器 + AMP scaler + 训练计数
  • Ctrl+C 自动安全保存，重启自动恢复，训练零丢失
  • 对手池注入：将 Small 模型作为高 Elo 对手注入 Standard 对手池，缓解自博弈同质化

深度生成模型 · 研究背景

研究背景与问题

生成模型的目标：将易于采样的初始分布（如高斯噪声）变换为符合真实数据分布的样本。

生成模型的统一范式

  • 初始分布 pinit（高斯噪声）→ 数据分布 pdata
  • 数据分布存在但数学形式未知，仅有有限样本（数据集）

连续归一化流（CNF）的训练困境

  • Continuous Normalizing Flows（CNFs）最大似然训练需反复求解 ODE 并计算 Jacobian 行列式，成本过高
  • 网络需满足可逆性约束，限制表达能力
核心动机：以"回归条件向量场"取代最大似然推断（Lipman 等，2022, NeurIPS）。
生成模型的统一范式：初始分布 → 数据分布（课程课件）
深度生成模型 · 核心方法

方法：条件向量场回归

针对每对（噪声、数据）构造具有解析解的条件概率路径，直接回归其向量场，实现免模拟（simulation-free）训练。

条件向量场

  • 条件路径 pt(x|z) 的向量场存在闭式解
  • 训练等价于监督回归（MSE），无需模拟 ODE 或计算 Jacobian

条件 ≡ 边缘

  • 优化条件损失等价于优化边缘损失
  • 以易算的条件版本逼近真正所需的边缘目标

直线调度（CondOT）

xt = (1−t)·x0 + t·z
  • 目标速度 ut = z − x0（常数）
  • 路径更直，采样步数显著减少

深度生成模型 · 实验实践

CFM MNIST 复现：模型架构与训练流程

基于 Pytorch-Conditional-Flow-Matching-Tutorial 复现，使用官方 4.8M 参数的 ConvBlock 残差网络，经过 150 epochs 预训练 + 50 epochs 微调，验证 Loss 降至 0.085，生成的手写数字接近真实 MNIST。

模型架构 (ConvBlock ResNet)

  • 输入: [B, 1, 28, 28] 灰度图像 + 时间 t
  • 主干: 8 层 ConvBlock (hidden_dim=256) + 残差连接
  • 核心组件:
    • 空洞卷积 (Dilated Conv) 扩大感受野
    • GroupNorm 归一化 + SiLU 激活
    • 时间嵌入 (Time Embedding) 融合
  • 输出: [B, 1, 28, 28] 预测的速度场 v

训练流程与配置

  • 数据: MNIST 手写数据集 (60k 训练 / 10k 测试)
  • 损失函数: 速度场 MSE 损失 (Mean Squared Error)
  • 优化器: AdamW (lr=5e-5 → 2e-5)
  • 训练技巧:
    • EMA (Exponential Moving Average, decay=0.999)
    • CosineAnnealing 学习率调度
    • 断点续训 (Checkpointing)
  • 采样: Euler 积分，T=100 步

深度生成模型 · 扩展实验

图像生成：从点云到图像表示

将 IMBR 字母由「无序点云」改为「32×128 图像」表示，复用 MNIST 上验证成功的 CFM 训练流程（4.8M ConvBlock 残差网络 + 随机配对 + EMA）。经过 65 epochs 微调，成功从高斯噪声生成清晰的 IMBR 字母。
IMBR 生成对比 (上排: 16 张模型生成 / 下排: 16 张 GT 真实)

核心问题与解决思路

  • 问题: 早期尝试将字母表示为无序点云，模型难以学到平滑的笔画结构。
  • 解决: 将生成任务重新定义为标准的像素级图像生成任务。
  • 效果: 成功利用 CNN 的局部相关性优势，直接迁移 MNIST 实验的成功经验。

实验配置

  • 数据: 32×128 在线渲染 IMBR 图像 (随机增强)
  • 模型: 复用 MNIST 的 4.8M ConvBlock 残差网络
  • 训练: 65 epochs, CFM Loss 0.259 → 0.040
  • 验证 Loss: 0.0396
结论: 任务的数据表示至关重要。将 IMBR 生成视为图像生成任务后，标准的 CFM 训练范式即可有效工作。这验证了流匹配在通用图像生成任务上的强大潜力。
Discussion & Future Work

A Thought on Flow Matching vs. Diffusion

Flow matching and diffusion models share core technologies and boundaries are not absolute. As we move towards real-world applications, a question arises regarding the optimization strategies.

Textbook Insight

"流匹配与扩散模型之间的边界并不绝对——两者的核心技术（条件控制、无分类器引导、隐空间建模等）可以高度共享。在连续时间表述下，二者都可以理解为学习从简单分布到数据分布的动力系统。"

Our Experiment

  • Successfully reproduced CFM on MNIST and IMBR.
  • Found CFM efficient (fewer steps) and stable.
  • Data representation is crucial for success.

If we have the opportunity to apply Flow Matching to solve problems in existing work, should we primarily migrate proven ideas from Diffusion models (e.g., Classifier-Free Guidance, latent space modeling), or should we focus on optimizing based on Flow Matching's own strengths (e.g., straight-line paths, efficiency)?
